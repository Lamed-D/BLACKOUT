Docker 실습 환경 선택

아래 명령은 저장소 루트에서 실행합니다. 공개 주소에서는 이 가이드를 읽고, 실습 서버는 Docker를 실행한 PC의 브라우저에서 엽니다.

Flask 게시판

docker compose --profile board up -d --build

127.0.0.1:9999에서 게시판과 기존 웹 보안 시나리오 훈련장을 엽니다.

PHP · 오류 노출과 세션

docker compose -f labs/php/compose.yaml up -d

http://127.0.0.1:8091 에서 실행 중인 설정을 읽습니다. 오류 표시, 오류 로깅, 버전 노출, HttpOnly, SameSite, MIME 유형 검사를 관찰하세요. 예를 들어 세션 쿠키에 HttpOnly가 빠진 사례와 실제 Set-Cookie 헤더를 비교하세요.

PHP 실행 명령에서 up -d를 logs --tail 50 또는 down으로 바꾸면 PHP 환경만 조회하거나 종료합니다.

접속 로그 판독

09:12:03  POST /login  401
09:12:08  POST /login  401
09:12:11  POST /login  200

마지막 요청에서 로그인이 성공했다고 판단할 수 있을까요?

판단 근거 확인

HTTP 200은 응답 처리 결과입니다. 실패 안내 페이지도 200을 반환할 수 있습니다. 같은 요청 ID의 인증 이벤트와 세션 발급 기록을 확인하세요.

게시글 수정 권한

글 작성자   지민
요청 계정   서준 (일반 회원)
작업       게시글 수정

자기 글만 수정할 수 있는 게시판입니다. 수정 버튼을 숨긴 뒤 서버에서 추가로 확인할 값은 무엇일까요?

권한 검사 확인

저장 시 서버가 인증한 계정 ID와 DB에 기록된 작성자 ID를 비교합니다. 이 요청은 작성자가 다르므로 거부합니다.

백업 복구 판단

01:00  백업 A 완료
02:10  잘못된 일괄 수정
03:00  백업 B 완료

문제 발생 직전 상태를 조사하려면 어떤 백업을 어디에 복원해야 할까요?

복원 순서 확인

별도 DB에 백업 A를 복원합니다. 이후 변경 기록이 있다면 02:10 직전까지 적용하고 영향을 받은 행을 대조합니다. 백업 B에는 잘못된 수정이 이미 포함되어 있습니다.
